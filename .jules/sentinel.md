## 2025-02-15 - Zip Slip Vulnerability in Custom Backup System
**Vulnerability:** A Path Traversal (Zip Slip) vulnerability existed in `BackupManager.kt` during archive extraction. The `extractArchive` method sequentially read `ZipEntry` objects from a `ZipInputStream` and concatenated `entry.name` directly with the output directory path (`File(outDir, entry.name)`).
**Learning:** The application implements a custom backup and restore mechanism (`:services:backup:BackupManager`) instead of relying solely on the Android Backup service. When manually extracting Zip archives using standard Java/Kotlin IO (`java.util.zip`), path validation is not handled automatically. A malicious backup archive containing relative path sequences (`../`) in its entry names could write files outside the intended cache directory, potentially overwriting internal app data or executing arbitrary code.
**Prevention:** Always validate extracted archive paths. Create a `File` object using the destination directory and the entry name, then verify that its `canonicalPath` strictly starts with the destination directory's `canonicalPath` plus a `File.separator`. This protects against both direct directory traversal (`../`) and partial directory name matches (e.g., target `/tmp/backup`, malicious target `/tmp/backup-malicious`).
